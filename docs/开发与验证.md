# 开发与验证

组件分工和依赖见[开发指南](DEVELOPER.md)。历史回归结果见[版本记录](history/README.md)。

## 本地调试

- Edge 在 `edge://extensions`、Chrome 在 `chrome://extensions` 开启开发者模式，加载本仓库目录。修改后重载扩展并刷新 B 站页面，Popup 改动需重新打开工具栏弹窗。
- 缩小排查范围时，页面代理和内容脚本看 B 站页的开发者工具，Popup 和后台分别从扩展管理页进入相应的调试界面。下载问题可结合面板脱敏诊断和浏览器下载记录核对失败阶段。

## 自动回归

在仓库根目录使用项目现有的 Node 测试入口。根据改动选择相关用例，也可一次运行全量本地回归。

```bash
node --test test/*.test.mjs
```

离线签名校验兼容入口为 `node test/test-wbi.mjs`、`conda run -n py312 python test/test_md5.py` 和 `conda run -n py312 python test/test_js_md5.py`，均检查当前页面代理实现，不读取已移除的 `lib/wbi.js`。匿名网络接口验证使用 `node test/test-api.mjs`（旧入口 `test/test-js-api.mjs` 等价）；这些网络脚本不属于离线回归，接口风控、网络和账号权限会影响结果。

涉及实际网络和合成时，可单独按锁文件安装测试依赖，再从仓库根目录发起验证。该脚本需要能访问 B 站与媒体 CDN，会覆盖 `test/_out/` 中的同名样本，运行后检查 Git 差异。

```bash
npm --prefix test ci
npm --prefix test run test:merge
```

指定公开样例时，在仓库根目录执行 `node test/test_merge_auto.mjs BV1GJ411x7h7`。

真实网络合成及 `node test/merge-local.mjs` 均加载仓库分发的 `lib/mp4-remux.iife.js` 和 `lib/m4s-mux.js`，包含本地修改及完整性检查。后者需要 `test/_out/video.m4s`、`test/_out/audio.m4s` 已存在。第三方来源、许可和修改说明见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)；ZIP 应同时包含说明和许可原文。

## 手动验证

| 场景 | 样例与检查 |
| --- | --- |
| 单视频 | [普通视频页](https://www.bilibili.com/video/BV1iV4k6mEbA)。检查 Chrome 和 Edge 点击下载时先选文件夹，取消后没有任务，重试会重新询问。分别验证 MP4、M4A 和重名保存。 |
| 视频页合集 | [合集视频页](https://www.bilibili.com/video/BV1794y127up)。检查默认打开列表，手动切到单视频后保持选择，关闭重开后再次默认显示列表。 |
| 多分 P | [选集视频页](https://www.bilibili.com/video/BV17G4y1P7Y4)。检查当前 P 下载、整队下载和失败重试。 |
| 按章节下载 | 用含多个分 P 和播放器章节的可访问投稿打开「单视频」。确认模式默认关闭，勾选前无章节请求。跨 P 选择，中间留空，验证目录只选一次且每章输出一个文件。检查 Range 请求跳过未选主体，并用清晰的音画标记核对非关键帧边界、时长、进度条拖动和音画同步。模拟分 P 元数据错误、错误 Range 响应、暂停、取消及写盘失败，检查重试范围。 |
| Chrome 批量保存 | 打开「下载前询问每个文件的保存位置」，测试分 P 队列与列表批量。每批只选一次文件夹，核对 MP4、M4A、封面的保存位置、重名顺延、取消选择和失败后重试。 |
| 列表与空间 | 打开可访问的 `/list/…`、UP 主首页或投稿页，检查长列表读取、可选条目、并行队列及页面切换。 |
| 官方剧集 | 打开当前账号能访问的官方剧集，检查可用媒体和集数展示。选择不可访问的剧集时核对受限提示。 |
| 合成与保存 | 选择可用的 DASH 片源，检查合成时关闭面板与取消。用 Chrome 和 Edge 分别确认下载记录、文件名及播放结果，涉及无痕保存时也在无痕窗口验证。 |

防休眠需在 Chrome 和 Edge 上使用较短的系统空闲休眠时间实测：长下载时切到后台、关闭面板，确认系统保持运行且允许熄屏；验证暂停全部、恢复、合成中暂停、取消、多个页面、刷新和关闭页面，以及原生保存完成后的释放。不要通过自动化主动让系统休眠。界面检查包括设置、Popup、错误提示和诊断导出，确认操作提示和脱敏内容正确。 页面不应显示右下角悬浮图标；从浏览器工具栏打开面板，检查 X 关闭后网页可正常点击，下载继续，重开可查看活动任务。并行列表任务卡应各自显示正确的「X/N」和标题，乱序完成、补位和重试后不串项。

备用公开样例可用于检查页面入口和下载链路。[BV1GJ411x7h7](https://www.bilibili.com/video/BV1GJ411x7h7)、[BV1244y137qJ](https://www.bilibili.com/video/BV1244y137qJ)、[BV1HfW2epEPi](https://www.bilibili.com/video/BV1HfW2epEPi)。

批量并行回归：将「批量同时下载数量」分别设为 1、3、5，检查活动任务数量与空位补充；只勾选原列表第 3、7 项，确认文件名使用 `_p1`、`_p2`。使用大小不同的视频制造乱序完成，核对视频、音频、封面的编号。覆盖暂停/恢复、单项取消、取消整队、磁盘失败和刷新恢复后重试，确认已保存内容不重复下载、未完成内容保留原编号。对长标题、自定义模板及清晰度降级确认后缀完整。Chrome、Edge 均需验证。Chromium 批量封面还需模拟请求或响应体停滞，检查取消整队、单项取消及超时后队列能够结束，迟到响应不写文件，下一批可以启动；不同页面的取消操作不得影响其他页面。

## 本地打包

在仓库根目录运行 Chromium 打包脚本。

```bash
conda activate py312
python scripts/pack.py
```

- 打包产出 `bilibili-downloader.zip`，扩展版本以 `manifest.json` 为准。
- 脚本按运行文件清单打包，包含 `power` 权限。提交前重新打包并查看归档，确认 `manifest.json` 位于根目录，包含所需运行资源。构建产物保留在本地。
- 替换透明母图 `assets/icon-source.png` 后，运行 `python scripts/gen_icons.py` 生成 `icons/` 和 `assets/` 中的各尺寸图标，并更新内容脚本的 `ICON_REV` 和 Popup 图标的版本参数。重载扩展后检查工具栏、弹窗和页面面板。
- GitHub Pages 的发布文件为 [隐私政策](index.html)、[FAQ](faq.html) 和 [.nojekyll](.nojekyll)。保留既有 URL 及 FAQ 锚点，发布后检查页面和跳转。
